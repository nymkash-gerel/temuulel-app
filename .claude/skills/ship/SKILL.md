# Deploy-ийн өмнөх шалгалт (/ship)

Production руу гаргахаас өмнө дараах шалгалтуудыг **дарааллаар** ажиллуул. Аль нэг нь унавал ЗОГС — тэр асуудлыг зассаны дараа л үргэлжлүүл. Хэрэглэгчийн зөвшөөрөлгүйгээр ХЭЗЭЭ Ч deploy бүү хий.

## 0. Юу deploy хийхийг тодорхойл

`git status` + `git diff main...HEAD --stat`-ээр энэ deploy-д юу орж байгааг харуул. Хэрэглэгчид товч дүгнэ.

## 1. Тест — `npm test`

Бүх unit тест ногоон болтол. Унавал: юу унасныг ил хэл, зас, дахин ажиллуул. (DB-тэй integration тест шаардлагатай бол `npm run test:integration` тусад нь.)

## 2. Build — `npm run build`

**0 алдаа** байх ёстой (CLAUDE.md шаардлага). Type алдаа / build алдаа гарвал зогс, зас.

## 3. Lint — `npm run lint`

ESLint цэвэр эсэх.

## 4. Аюулгүй байдлын аудит — `security-auditor` sub-agent

`security-auditor` агентыг ажиллуул (энэ branch-ийн `git diff main...HEAD` дээр). CRITICAL / HIGH олдвол **deploy зогсоо** — заавал зас. MEDIUM / LOW бол хэрэглэгчид харуулж, шийдвэрийг нь ав.

## 5. Migration шалгалт (шинэ migration байвал)

`git diff main...HEAD --name-only`-д `supabase/migrations/` өөрчлөлт байвал:
- `migration-reviewer` sub-agent-аар шалгуул.
- `npm run gen:types:check`-ээр `database.types.ts` бодит schema-тай синхрон эсэхийг батал.
- **Production DB-д migration хэрэглэх шаардлагатайг** сануул — код нь шинэ RPC/хүснэгт дуудвал migration-ыг ЭХЛЭЭД хэрэглэнэ.

## 6. Дүгнэлт + deploy санал (гүйцэтгэхгүй)

Бүх шалгалтын үр дүнг хүснэгтээр дүгнэ (✅/❌). Бүгд OK бол л:
> "Бүх шалгалт цэвэр. `vercel deploy --prod` ажиллуулах уу? — надаас баталгаа авсны дараа."

Deploy командыг **өөрөө битгий ажиллуул** — хэрэглэгч тодорхой "тийм" гэсний дараа л. (Тэмүүлэл Vercel дээр deploy хийгддэг.)

## Тэмдэглэл

- Аль нэг шалгалт унасныг НУУХ ёсгүй — бодит үр дүнг ил тайлагна.
- Хэрэглэгч тодорхой алгасахыг хүсээгүй бол алхам бүү алгас.
