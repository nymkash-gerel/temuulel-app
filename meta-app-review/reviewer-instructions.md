## Instructions (paste into Meta)

Temuulel is an AI customer-service and order-management platform for small
businesses in Mongolia. A business owner connects their Facebook Page once, and
our AI then answers customer messages in Mongolian and collects orders.

Most of the product interface is in Mongolian, so please follow these steps
exactly.

**Test account**

- URL: `<<https://APP_DOMAIN>>/login`
- Email: `<<REVIEWER_EMAIL>>`
- Password: `<<REVIEWER_PASSWORD>>`

This account already has a store set up with sample products, so you can go
straight to the Page connection.

**Steps**

1. Sign in at `<<https://APP_DOMAIN>>/login` with the credentials above.
2. In the left sidebar, open **Тохиргоо → Холболтууд** (Settings → Integrations).
   Direct link: `<<https://APP_DOMAIN>>/dashboard/settings/integrations`
3. Click **Facebook холбох** (Connect Facebook). You are sent to the Facebook
   OAuth dialog.
4. Grant access and select a Facebook Page you administer. You are returned to
   our Page-selection screen; choose the Page and confirm.
   The Page now shows as connected on the Integrations screen.
5. Open Messenger as a **customer** (a different Facebook account, or the Page's
   public m.me link) and send a message in Mongolian, for example:
   `Сайн байна уу, ямар бараа байна?` ("Hello, what products do you have?")
6. Within a few seconds the Page replies automatically with a product list. This
   reply is generated by our AI and sent using **pages_messaging**.
7. Continue the conversation to place an order, for example:
   - `Хоёр дахийг авъя` ("I'll take the second one")
   - then reply with a name, phone number and address when asked.
8. Back in the dashboard, open **Захиалга** (Orders) —
   `<<https://APP_DOMAIN>>/dashboard/orders` — and confirm the order created from
   that conversation appears there. The conversation itself is visible under
   **Чат** (Chat).

**Notes**

- All replies are sent only inside the 24-hour standard messaging window, in
  response to a customer-initiated message. We do not send promotional messages
  outside that window.
- Instagram permissions follow the same flow: on the Integrations screen choose
  **Instagram холбох** and repeat steps 3–8 using Instagram Direct.

## Permissions requested by the code

`src/app/api/auth/facebook/route.ts` requests these scopes. Every one of them
needs a description and a screencast in the submission.

| Permission | Why we request it | Description written? |
|---|---|---|
| `pages_show_list` | list the Pages the owner manages so they can pick one | ✅ `permission-descriptions.md` |
| `pages_messaging` | send the AI replies — the core of the product | ✅ |
| `pages_manage_metadata` | subscribe the Page to the messaging webhook | ✅ |
| `pages_read_engagement` | read Page name/metadata when confirming which Page was connected | ⚠️ **see below** |
| `business_management` | list Pages owned through Business Manager, which most of our merchants use | ⚠️ **see below** |
| `instagram_manage_messages` | same AI replies over Instagram Direct | ✅ |
| `instagram_basic` | link the Instagram professional account to the Page | ✅ |

### pages_read_engagement — description to submit

> Temuulel uses pages_read_engagement to read basic Page information — the Page
> name and id — after a business owner connects their Page, so the dashboard can
> show them which Page is currently connected and confirm the connection
> succeeded. We do not read post content, comments or insights with this
> permission. It is used during the connection step and whenever the owner
> revisits the Integrations settings screen to verify their connection.

### business_management — description to submit

> Most Mongolian businesses administer their Facebook Page through a Business
> Manager rather than as a personal Page admin. Temuulel uses
> business_management so that pages_show_list can enumerate those
> Business-Manager-owned Pages during connection; without it the Page list is
> empty for these owners and they cannot connect at all. We use it only to list
> the Pages the person already manages so they can choose one. We do not create,
> modify or delete any business assets, and we do not access advertising or
> billing data.

## Blockers

**Meta review cannot be submitted until the app is deployed to a stable public
domain.** Reviewers sign in and drive the real OAuth flow, so they need:

- a permanent URL (Vercel preview URLs change per deployment and are typically
  protected), registered as the OAuth redirect URI;
- `NEXT_PUBLIC_APP_URL` set to that domain at **build** time — it is inlined
  into the client bundle, and the OAuth redirect URI is built from it;
- a working production database, so the reviewer's Page connection and the
  resulting order actually persist.

There are currently **zero production deployments**. So the ordering is:

> production Supabase → env vars → Vercel production deploy + domain →
> reviewer test account → screencast → **submit**

This corrects an earlier plan that had Meta review starting on day one in
parallel with everything else. The multi-week review clock only starts once the
above is done, so the deployment is what to hurry — not the paperwork, which is
finished apart from the video.
